# Build 024 – LineageOS 22.2 ARM64 first-stage init laboratory

**Branch:** `feature/build024-lineageos-arm64-init-lab`  
**Reference:** LineageOS 22.2, Android 15, `android_system_core` at `lineage-22.2`.  
**Status:** Host tooling implemented and synthetic tests passed. **No actual
LineageOS first-stage `/init` has been supplied, run or verified on QEMU.**

## What this build does

- Read-only inspection of a locally checked-out official LineageOS
  `android_system_core` source repository: remote, branch/commit and three
  relevant source files. Detached checkouts are accepted with explicit
  uncertainty. No source authenticity or commit-signature proof is claimed.
- Host-only ABI validation of a **user-provided, already built** ARM64 Android
  first-stage `/init`: ELF64/AArch64, no PT_INTERP/DT_NEEDED, explicitly pinned
  SHA-256. A plausible ELF is **not** proof that it came from LineageOS.
- If such a binary is available, stage its **unchanged bytes** as `/init` in
  an isolated deterministic gzip/newc QEMU initramfs. No stub substitutes
  for genuine Android init. All output paths must be new.
- Reuse the bounded, NIC-/disk-free QEMU runner from Build 023, followed by
  a strict log + QEMU metadata + staging SHA-256 correlation.
- Optionally recognize the literal `init first stage started!` marker observed
  in the official LineageOS first-stage init source. This is only *reported*
  text evidence; no cryptographic binary provenance/working Android services
  or completed boot is inferred.

## Why no immediate full LineageOS build?

The **upstream Linux 6.6.162 QEMU-virt kernel** in Build 023 is not an
Android-certified `android15-6.6` GKI build. Passing Binder version ioctls,
selinuxfs and memory smoke probes does not establish a working Android init,
property service, SELinux policy, VINTF, HALs, or LineageOS system image.

Cloning just `android_system_core` gives **source files, not a buildable,
genuine Android `/init` binary by itself**. Compiling Android init requires
a matching platform build tree and target. This repository has no proven
Samsung Q60T device target; do not reuse a random other-device boot image.

## Debian commands: source-only audit (available now)

All paths here are laboratory directories, unrelated to Samsung storage.

```bash
cd /opt/samsung-atv-lab
git clone --depth 1 --branch lineage-22.2 \
  https://github.com/LineageOS/android_system_core.git \
  lineageos-system-core

cd /opt/samsung-atv-lab/q60t-github
python3 q60t_lineageos_preflight.py \
  --source /opt/samsung-atv-lab/lineageos-system-core \
  --output /opt/samsung-atv-lab/build024-source-audit-001.json
```

Expected status: `LINEAGEOS_SOURCE_AUDITED_INIT_BINARY_NOT_SUPPLIED`.
This **does not** mean Android booted or that we already have `/init`.

## Optional: real Android `/init` artifact, only when available

First obtain a trustworthy ARM64 `/init` from a separately built matching
LineageOS source tree. `INIT_BINARY` below is a **placeholder**, not a file
downloaded or generated by these scripts.

```bash
INIT_BINARY=/opt/samsung-atv-lab/lineageos-artifacts/init
sha256sum "$INIT_BINARY"

python3 q60t_lineageos_preflight.py \
  --source /opt/samsung-atv-lab/lineageos-system-core \
  --init-binary "$INIT_BINARY" \
  --expected-init-sha256 REPLACE_WITH_ACTUAL_64_HEX_SHA256 \
  --output /opt/samsung-atv-lab/build024-init-preflight-001.json

python3 q60t_lineageos_initramfs.py \
  --init-binary "$INIT_BINARY" \
  --preflight /opt/samsung-atv-lab/build024-init-preflight-001.json \
  --output /opt/samsung-atv-lab/build024-lineage-initrd-001.cpio.gz \
  --report /opt/samsung-atv-lab/build024-lineage-stage-001.json

python3 q60t_arm64_qemu.py \
  --kernel /opt/samsung-atv-lab/build023-arm64-kernel-003/arch/arm64/boot/Image \
  --initrd /opt/samsung-atv-lab/build024-lineage-initrd-001.cpio.gz \
  --output-dir /opt/samsung-atv-lab \
  --run-id lineage024-001 --timeout 60

python3 q60t_lineageos_guest_result.py \
  --log /opt/samsung-atv-lab/qemu-serial-lineage024-001.log \
  --qemu-metadata /opt/samsung-atv-lab/qemu-meta-lineage024-001.json \
  --stage-report /opt/samsung-atv-lab/build024-lineage-stage-001.json \
  --preflight /opt/samsung-atv-lab/build024-init-preflight-001.json
```

The output may report first-stage log evidence, a kernel panic, or simply no
marker; these are all meaningful diagnostic outcomes. A nonpersistent QEMU
boot attempt **does not** validate LineageOS runtime, security policy, GPU,
HDMI, remote control or any Samsung hardware.
